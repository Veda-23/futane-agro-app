# Futane Agro App – Health API Documentation

## Overview
The **Health** API provides two endpoints that expose application health information and a set of system metrics.

| Endpoint | Description | Response Model |
|----------|-------------|----------------|
| `GET /api/health` | Basic health check – returns status **UP**, a timestamp and the response time in ms. | `HealthResponse` |
| `GET /api/health/detailed` | Detailed health check – includes application version, uptime, JVM memory usage, CPU load, disk and network metrics. | `DetailedHealthResponse` |

Both endpoints are documented in Swagger/OpenAPI and are available via the generated Swagger UI (exposed at `/swagger-ui.html` when the application runs).

## Swagger Annotations
The controller uses Swagger annotations (`@Api`, `@ApiOperation`, `@ApiResponses`) to describe each operation. The generated OpenAPI spec includes:
- Operation IDs (`getBasicHealth`, `getDetailedHealth`)
- Response schemas for `HealthResponse` and `DetailedHealthResponse`
- Example responses (generated automatically by Springfox)

## Actuator Integration
A custom `HealthMetricsIndicator` exposes the same metrics through Spring Boot Actuator:
```
GET /actuator/health
```
The actuator payload contains `memory`, `cpu`, and `uptimeMs` details, making it easy to consume by monitoring tools such as Prometheus.

## Metric Collection Service
All metric logic lives in `HealthMetricsService`. This service can be injected elsewhere in the codebase for reuse, e.g. scheduled jobs or other controllers.

## Running the Application
```bash
# Build the project
./mvnw clean package

# Run locally
java -jar target/futane-agro-0.0.1-SNAPSHOT.jar
```
Visit `http://localhost:8080/api/health` or `http://localhost:8080/api/health/detailed` to see the health data.
