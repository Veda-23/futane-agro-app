Chapter 3: Zero-Trust Cryptographic Security Architecture

Futane Agro ERP implements a state-of-the-art Zero-Trust security paradigm inspired by defense-in-depth financial systems. The fundamental principle is: "Never Trust, Always Verify." Every API request, user session, and database transaction undergoes rigorous cryptographic validation.

3.1 Cryptographic Password Hashing & Key Derivation

User credentials are encrypted using Password-Based Key Derivation Function 2 (PBKDF2) combined with HMAC-SHA-256. Each password hash incorporates a 128-bit cryptographically secure random salt generated via java.security.SecureRandom, iterated across 10,000 computation cycles: 

KeySpec spec = new PBEKeySpec(password.toCharArray(), salt, 10000, 256);
SecretKeyFactory factory = SecretKeyFactory.getInstance("PBKDF2WithHmacSHA256");
byte[] hash = factory.generateSecret(spec).getEncoded();
String secureRecord = Base64.getEncoder().encodeToString(salt) + ":" + Base64.getEncoder().encodeToString(hash);

3.2 Dual-Phase Challenge-Response Multi-Factor Verification

Authentication proceeds through a two-stage zero-trust challenge:

  1. Phase 1: Credential Verification: The client submits username and password over TLS. The server verifies credentials against PBKDF2 hash. If valid, an ephemeral 6-digit Time-Based One-Time Password (OTP) is generated and associated with a high-entropy session nonce valid for exactly 300 seconds.
  2. Phase 2: Cryptographic Token Minting: The user enters the OTP challenge code. Upon verification, the server issues a digitally signed JSON Web Token (JWT) utilizing HMAC-SHA-512 with embedded claims (User ID, Role, Tenant ID, Expiration).

6.2 Replay Protection via Ephemeral Nonces

To prevent transaction replay attacks across financial or inventory mutations, every modifying REST request (POST, PUT, DELETE) must present a single-use UUIDv4 nonce in the X-Request-Nonce header. The server records used nonces in an in-memory sliding window cache valid for 300 seconds. If an identical nonce is presented within the window, the request is immediately rejected with HTTP 409 Conflict.

Chapter 9: Zero-Trust Cryptographic Token Lifecycle & Ephemeral Nonce Protocols

Futane Agro ERP enforces a Zero-Trust security paradigm across all architectural boundaries. No user, service, or network interface is implicitly trusted, regardless of whether access originates from within the plant local area network or a remote mobile endpoint.

9.1 Cryptographic Token Structure & Signing

Authentication tokens are formatted as standard RFC 7519 JSON Web Tokens (JWT) signed using the HMAC-SHA-512 cryptographic algorithm with a 512-bit cryptographically secure pseudorandom key (CSPRNG) stored in the environment configuration:

Token Attribute Internal Specification Security Invariant
Algorithm Header {"alg": "HS512", "typ": "JWT"} Rejects none algorithm; enforces explicit HS512 validation
Payload Claims sub (Username), role (RBAC Role), tenant_id, exp, iat, jti Payload is base64url encoded; no plaintext sensitive data stored
Token Lifespan 28,800 seconds (8 hours standard shift duration) Tokens cannot be refreshed after expiration; re-login required
Session Invalidation Server-side blacklist maintained in Guava cache Logout immediately places jti (JWT ID) in blacklist until expiry

9.2 Ephemeral Nonce & Anti-Tamper Verification Flow

Financial mutations and state-changing requests undergo a three-stage anti-tamper verification pipeline prior to controller execution:

  1. Header Extraction: The ZeroTrustSecurityFilter extracts X-Request-Nonce and X-Client-Timestamp headers.
  2. Drift Validation: The server verifies that |System.currentTimeMillis() - clientTimestamp| < 30,000 ms. Requests outside the 30-second window are rejected with 400 Bad Request (Clock Skew).
  3. Cache Verification: The nonce UUID is checked against an atomic concurrent hash map. If present, the request is flagged as a replay attack and rejected with 409 Conflict. If unique, the nonce is stored with a 300-second TTL.
  4. Audit Logging: The transaction signature is appended to the audit_logs repository, binding the authenticated identity to the mutated state.

Chapter 3: Analytical Materialized & Relational Database Views

To maximize query execution velocity on dashboards and analytics without imposing computational overhead on transactional tables, four optimized analytical views are deployed:

View 1: v_daily_financial_summary

Aggregates daily sales billed, customer payment receipts collected, factory expenses disbursed, and computed net cash flow.

CREATE OR REPLACE VIEW v_daily_financial_summary AS
SELECT 
  d.date_val AS transaction_date,
  COALESCE(SUM(s.total_amount), 0.00) AS total_sales_billed,
  COALESCE(SUM(p.amount), 0.00) AS total_payments_received,
  COALESCE(SUM(e.amount), 0.00) AS total_expenses_paid,
  (COALESCE(SUM(p.amount), 0.00) - COALESCE(SUM(e.amount), 0.00)) AS net_daily_cashflow
FROM (
  SELECT invoice_date AS date_val FROM invoices
  UNION SELECT payment_date FROM payments
  UNION SELECT expense_date FROM expenses
) d
LEFT JOIN invoices s ON s.invoice_date = d.date_val
LEFT JOIN payments p ON p.payment_date = d.date_val
LEFT JOIN expenses e ON e.expense_date = d.date_val
GROUP BY d.date_val
ORDER BY d.date_val DESC;

View 2: v_inventory_valuation

Computes live finished goods inventory valuation and identifies stock items falling below safety reorder buffers.

CREATE OR REPLACE VIEW v_inventory_valuation AS
SELECT 
  id,
  item_name,
  crate_type,
  current_stock,
  minimum_threshold,
  unit_cost,
  (current_stock * unit_cost) AS total_valuation_inr,
  CASE 
    WHEN current_stock <= minimum_threshold THEN 'CRITICAL_REORDER'
    WHEN current_stock <= (minimum_threshold * 1.5) THEN 'LOW_STOCK'
    ELSE 'HEALTHY'
  END AS inventory_status
FROM inventory;

View 3: v_machine_oee_metrics

Tracks Overall Equipment Effectiveness (OEE) metrics, breakdown frequency, and operational scrap ratios per injection molding machine.

CREATE OR REPLACE VIEW v_machine_oee_metrics AS
SELECT 
  m.id AS machine_id,
  m.machine_code,
  m.machine_name,
  m.clamping_force_tons,
  m.status,
  COUNT(DISTINCT p.id) AS total_shifts_run,
  COALESCE(SUM(p.successful_crates), 0) AS total_crates_produced,
  COALESCE(SUM(p.rejected_crates), 0) AS total_crates_rejected,
  ROUND(AVG(p.efficiency_pct), 2) AS average_efficiency_pct,
  COALESCE(SUM(b.downtime_hours), 0.00) AS total_downtime_hours
FROM machines m
LEFT JOIN production_ppd p ON p.machine_id = m.id
LEFT JOIN machine_breakdowns b ON b.machine_id = m.id
GROUP BY m.id, m.machine_code, m.machine_name, m.clamping_force_tons, m.status;

View 4: v_tax_liability_ledger

Provides a real-time GST tax audit register summarizing monthly CGST, SGST, IGST liabilities and total outward taxable turnover.

CREATE OR REPLACE VIEW v_tax_liability_ledger AS
SELECT 
  EXTRACT(YEAR FROM invoice_date) AS tax_year,
  EXTRACT(MONTH FROM invoice_date) AS tax_month,
  COUNT(id) AS total_invoices_issued,
  SUM(subtotal) AS total_taxable_turnover,
  SUM(cgst_amount) AS total_cgst_liability,
  SUM(sgst_amount) AS total_sgst_liability,
  SUM(igst_amount) AS total_igst_liability,
  SUM(cgst_amount + sgst_amount + igst_amount) AS total_gst_payable,
  SUM(grand_total) AS total_gross_billed
FROM invoices
GROUP BY EXTRACT(YEAR FROM invoice_date), EXTRACT(MONTH FROM invoice_date)
ORDER BY tax_year DESC, tax_month DESC;

2. Standard Operating Workflow — Execution Steps

1. Shift Handover & Machine Inspection: The incoming shift operator verifies hydraulic oil levels, chiller water temperature (12°C - 15°C), and barrel heater zone temperatures (210°C - 235°C for Polypropylene).

2. Hopper Feed & Granule Intake: Ensure virgin PP granules and color masterbatch (1.5% - 2.0% ratio) are properly blended and loaded into the machine vacuum hopper dryer.

3. First Shot Quality Verification: Inspect the first 3 molded crates for sink marks, short shots, flash, or color streaking. Measure dimensional tolerance across top lip and base ribs (+/- 1.5mm standard).

4. Continuous Production Run: Monitor automated cycle time (42 seconds for 500ml crates, 52 seconds for 1L agro crates). Crates are ejected onto the conveyor belt.
